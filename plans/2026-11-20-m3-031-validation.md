## Session failure diagnosis

`Instant.now()` can include sub-millisecond precision. Room's existing converter
stores epoch milliseconds. The first checkpoint therefore saved successfully, but
the next checkpoint compared the reloaded timestamp with the original Instant
using exact equality and rejected the same session as an ID collision. Existing
tests used whole-second Instants and missed this device behavior.

A real Room regression with a nanosecond timestamp failed before the change at
`SessionRepository`'s identity guard. Identity now compares epoch milliseconds,
while retaining the book, browsing and captured-minimum guards. No storage quota
change or destructive recovery is involved. Time that was never successfully
recorded by 0.3.0 is not fabricated.

## Combined audit

One combined audit found two related edge cases. Both were corrected and cleared
by a scoped follow-up:

- Editing a multi-day read-through to one calendar day could reject it because
  the hidden start/end times were inverted. Validate the selected dates first and
  clamp the end to the start when needed on the same day.
- A qualifying session shorter than one minute could show `0m` in the held
  celebration. Show seconds for positive sub-minute totals.

Regressions exercise the native calendar and the held 35-second celebration.
