# M5 — highlights, notes and search implementation plan

> **For agentic workers:** Use subagent-driven-development for substantial implementation tasks. The author requests batched verification and one consolidated audit rather than separate agents for individual checks. Continue through the signed release handover without milestone merge.

**Goal:** Save and revisit EPUB passages, highlights and notes in both reading modes, browse/search every non-ignored book's annotations and bookmarks, and share a book's notes as Markdown.

**Architecture:** Room 8 adds persistent highlights behind `:library:notes`; `:feature:notes` owns reusable editing, global/per-book browsing and export. Reader adapters translate stored locator ranges to Readium decorations or continuous DOM ranges. Existing search, bookmarks, file identity and tracking remain authoritative. Notes never depend on a source file remaining present.

**Tech stack:** Existing Kotlin/Compose/Hilt/Room/Coroutines, Readium 3.2, local WebView JavaScript and Android intents. No new third-party dependency or toolchain.

## Global constraints

- Book files are read-only. Source edits are never used for annotations.
- History is permanent except explicit Forget; missing files keep notes, ignored books are excluded from all Notes lists/exports and un-ignore restores them.
- Network lives only in `:data:matching`; no INTERNET permission or remote requests.
- DRM is labelled Protected, never decrypted. External dictionary/share actions are explicit user actions.
- Every Room schema change ships with a migration and a migration test.
- Application ID `com.kmab.deft`; minSdk26, target36; persistent signing key, R8 and resource shrinking.
- Work on `feat/m5-notes` from main `4ae7a17`; version `0.5.0-1`. Author `Samuel Worash Getaneh <samuelworash@gmail.com>`.
- Preserve the user's dirty `plans/m1-test-checklist.md`. Do not merge M5 without acceptance. Use installed SDK at D:/Code/android-sdk, Gradle JDK17 and test JDK21. Only missing dependencies may download.
- Four highlight colors: purple, green, amber, gray, plus NONE. Selecting text alone never writes. NONE retains a saved nonblank note; NONE with no note removes/does not create the annotation.
- Fixed-layout page-note creation belongs to M8; do not add inert controls or future format engines in M5.

## Shared interfaces

`core/model/.../HighlightColor.kt`:
```kotlin
enum class HighlightColor { PURPLE, GREEN, AMBER, GRAY, NONE }
```
`core/database/.../entity/HighlightEntity.kt`: `id: Long = 0`, `bookId: Long`, `locator: String`, `text: String`, `color: HighlightColor`, `note: String?`, `totalProgression: Double`, `createdAt: Instant`, `updatedAt: Instant`. FK Book CASCADE only on explicit Forget, indexed bookId and unique (bookId, locator).

`library/notes/.../NotesModels.kt`:
```kotlin
data class HighlightDraft(
    val bookId: Long, val locator: String, val text: String,
    val color: HighlightColor = HighlightColor.NONE, val note: String? = null,
    val totalProgression: Double = 0.0, val id: Long? = null,
)
enum class NoteType { HIGHLIGHT, NOTE, BOOKMARK }
data class NoteFilter(
    val bookId: Long? = null, val color: HighlightColor? = null,
    val type: NoteType? = null, val query: String = "",
)
```
`NoteEntry` is a read projection with `id`, `bookId`, `bookTitle`, `authors`, `bookFormat`, `missing`, `drmProtected`, `locator`, `totalProgression`, `text`, `note`, nullable `color`, nullable `label`, `createdAt`, `updatedAt`, and `type`. Entry type is BOOKMARK for bookmarks, NOTE for colorless notes, HIGHLIGHT for colored passages; filtering NOTE includes any nonblank note and filtering HIGHLIGHT includes any colored passage, including one with a note. Use (type-is-bookmark, id) for stable identity, not text/title.

`NotesRepository @Inject constructor(db: AppDatabase)` exposes:
```kotlin
fun observe(filter: NoteFilter = NoteFilter()): Flow<List<NoteEntry>>
fun observeHighlights(bookId: Long): Flow<List<HighlightEntity>>
suspend fun saveHighlight(draft: HighlightDraft): Long?
suspend fun deleteHighlight(id: Long)
suspend fun renameBookmark(id: Long, label: String)
suspend fun deleteBookmark(id: Long)
suspend fun exportMarkdown(bookId: Long): String
```
Mutation validation and timestamp preservation live here. Save is transactional, preserves createdAt/identity on updates, and never changes the source book. Empty colorless records disappear. Export contains title/author and ordered quote/note/bookmark locations, with Markdown escaping and no private file URIs. Search is literal, case-insensitive over text/note/label/title/author; `%` and `_` are ordinary input. No remote search.

`feature/notes/.../HighlightEditor.kt` exposes a reusable Composable:
```kotlin
fun HighlightEditor(
    draft: HighlightDraft,
    onSave: (HighlightDraft) -> Unit,
    onDismiss: () -> Unit,
    onDelete: (() -> Unit)? = null,
    busy: Boolean = false,
)
```
The editor keeps a rotation-safe draft, labelled color choices (including none), selected passage, note field and pinned save/cancel actions, with explicit deletion confirmation. Use shared Deft colors/components; caller supplies notices and async busy state. No persistence until Save or confirmed Delete.
